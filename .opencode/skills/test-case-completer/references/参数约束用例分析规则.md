# 参数约束用例分析规则

## 核心前提

- 基站端有约束校验机制，所有不符合约束的配置在 MML 命令执行阶段就会被拒绝，**不会出现不符合约束的配置实际生效的情况**
- 触发方式：执行 MML 命令时即校验
- 校验结果：拒绝配置并返回错误（错误码 + 错误信息）
- 配置不会部分生效：要么命令执行成功，要么被拒

测试的核心目标是：**验证约束校验是否正确拦截非法配置。**

## 约束类型

| 约束类型 | 描述 | 示例 |
|----------|------|------|
| 联动约束 | A 开启时 B 必须满足条件 | 开启 CA 时辅载波频段必须兼容 |
| 互斥约束 | A 和 B 不能同时存在 | DSS 模式与独立部署互斥 |
| 范围约束 | 参数值必须在有效区间内 | 发射功率 0-50dBm |
| 枚举约束 | 参数只能取特定离散值 | 子载波间距 15/30/60/120 kHz |
| 条件约束 | 参数可配置性取决于上下文状态 | NSA 模式下某些参数不可配置 |
| 共存约束 | 多功能共存时的限制 | 4G/5G 共站总功率上限 |

## 用例名称解析模式

```
【参数约束】{编号}：{约束描述}
```

从约束描述中提取：
- **被约束对象**：哪个参数/功能受约束
- **约束条件**：什么条件下约束生效
- **约束结果**：允许还是禁止某种操作

## 检查维度

### 1. 约束规则完整性

- [ ] 约束类型是否明确？（联动/互斥/范围/枚举/条件/共存）
- [ ] 被约束的参数路径是否明确？（如 NRCell.CASwitch）
- [ ] 约束条件是否明确？（无条件禁止 vs 特定条件下禁止）
- [ ] 条件参数的路径是否明确？（如约束条件依赖的开关/参数）
- [ ] 约束违反时的错误码是否明确？

### 2. 前置条件检查

- [ ] 主对象（主小区/主网元）配置是否完整？（频段、带宽、制式、类型）
- [ ] 从对象（辅小区/辅网元）是否需要预先创建？配置是否完整？
- [ ] 被约束参数的当前值是否明确？
- [ ] 约束条件涉及的依赖参数状态是否明确？（如需要先打开某个开关）
- [ ] 小区是否需要预先创建？

### 3. 测试步骤检查

- [ ] 操作方式是否明确？（MML 命令的具体内容或参数名）
- [ ] 负向步骤（约束禁止的操作，预期被拒绝）是否完整？
- [ ] 正向步骤（约束允许的操作，预期成功）是否有？
- [ ] 成功后需要验证什么？（查询参数？观察业务？）
- [ ] 互斥/联动约束是否需要测试顺序？（先A后B vs 先B后A）
- [ ] 中间状态的清理是否需要？（第一步成功后第二步被拒，第一步需要回退吗？）
- [ ] 是否需要测试批量下发场景？

### 4. 预期结果检查

- [ ] 正向操作的成功标准是否可判定？（不只是"成功"，要明确验证什么）
- [ ] 负向操作的拒绝标准是否可判定？（错误码、错误信息）
- [ ] 拒绝后是否需要查询确认参数未变？

### 5. 后置条件检查

- [ ] 是否需要删除创建的主对象？
- [ ] 是否需要删除创建的从对象？
- [ ] 是否需要关闭功能开关/恢复依赖参数？
- [ ] 无需恢复？

## 提问模板

### 约束规则类

```
Q: 这个约束属于哪种类型？
   A. 联动约束（A开启时B必须满足条件）
   B. 互斥约束（A和B不能同时存在）
   C. 范围约束（参数值有上下限）
   D. 枚举约束（参数只能取特定值）
   E. 条件约束（可配置性取决于上下文）
   F. 其他（请说明）
```

### 前置条件类

```
Q: 测试需要什么环境？
   A. 需要创建单个小区
   B. 需要创建多个小区（如主载波+辅载波）
   C. 基站默认配置即可
   D. 其他（请说明）

Q: 主小区的制式是？
   A. SA
   B. NSA

Q: 主小区的频段是？
   A. FDD N1
   B. TDD N41
   C. TDD N78
   D. 其他（请说明）

Q: 主小区的带宽是？
   A. 10M
   B. 20M
   C. 30M
   D. 40M
   E. 50M
   F. 100M
   G. 其他（请说明）

Q: 主小区的类型是？
   A. 普通小区
   B. 其他（请说明）

Q: 需要创建辅小区/辅对象吗？
   A. 不需要
   B. 需要（请提供频段、带宽等配置）

Q: 约束条件涉及的依赖参数是什么？
   A. 无依赖
   B. 需要先设置某个参数（请提供参数路径和值）
```

### 测试步骤类

```
Q: 被约束的参数路径是什么？
   （请提供，如 NRCell.CASwitch）

Q: 约束的是单个参数还是一类参数？
   A. 单个参数
   B. 一类参数（如所有SA专用参数）
   C. 不确定

Q: 这个用例是正向还是负向？
   A. 负向（约束禁止，预期被拒绝）
   B. 正向（约束允许，预期成功）
   C. 需要同时覆盖正向和负向

Q: 操作成功后需要验证什么？
   A. 查询参数值确认已生效
   B. 观察业务变化
   C. 不需要验证

Q: 需要覆盖哪些场景？
   A. 仅单参数设置
   B. 仅批量参数设置
   C. 两者都需要覆盖

Q: 需要测试操作顺序吗？（如互斥约束先A后B vs 先B后A）
   A. 不需要，单顺序即可
   B. 需要两种顺序都测
```

### 预期结果类

```
Q: 配置被拒绝时的错误码是什么？
   （请提供错误码）

Q: 除了错误码，还有错误信息吗？
   A. 有（请提供关键字）
   B. 没有，只有错误码
```

### 后置条件类

```
Q: 测试后需要删除哪些对象？
   A. 仅删除主小区
   B. 删除主小区和辅小区
   C. 不需要删除

Q: 除了删除小区，还需要其他清理吗？
   A. 恢复参数到默认值
   B. 关闭功能开关
   C. 以上都需要
   D. 不需要
   E. 其他（请说明）

Q: 测试过程中第一步操作成功但后续被拒，第一步的状态需要回退吗？
   A. 需要回退（如先关掉已开启的功能）
   B. 删除小区时会自动清理
   C. 不需要
```
