# 测试用例完备性补全

解析测试脚本框架中的用例注释，识别隐藏/缺失信息，通过对话逐个澄清后输出完整的注释块。

## 输入

Python测试脚本框架，类注释中包含 `@TestcaseNumber`、`@TestcaseName`、`@PreCondition`、`@TestStep`、`@TestResult`、`@PostCondition` 等字段。

## 输出

补全所有字段后的完整注释块，可直接替换原注释。

## 工作流程

### 阶段一：理解用例

1. 提取 `@TestcaseName`，从 `【类型】` 标签识别用例类型
   - 无标签时根据关键词判断
   - 无法判断时询问用户
2. 从用例名称提取已有信息，标记模糊词为待澄清项
3. 逐字段检查：空字段、模糊描述、步骤跳跃
4. 加载对应分析规则（references/下），按规则生成检查项
5. 查找已完成的相似用例：
   - 在当前目录下搜索同一专题下已补全的测试脚本
   - 提取其中的注释信息作为参考
6. 向用户说明已明确的信息和待澄清项数量，直接进入第一个问题

### 阶段二：逐项澄清

按分析规则中的检查维度和提问模板，逐个提问：

- 一次一个问题，给选项让用户选择
- **当存在已完成的相似用例时，选项中带上相似用例的具体值，格式为"（同 TC_000001）"**
- 当前用例名称中已有推断值时，也作为选项提供
- 基于回答推导下一个问题
- 发现新信息时可回退确认
- 所有检查项明确后进入阶段三

### 阶段三：一次性呈现

1. 一次性输出完整注释块，不逐段确认
2. 最后问："需要调整的地方吗？"
3. 用户反馈后修改，直到确认

## 规则

- 不写实现代码——只分析和补全注释
- 具体的检查维度、提问方式、选项设计由分析规则决定
- 每种用例类型在 `references/` 下有独立的分析规则文件
- 新增类型：在 `references/` 下添加文件，结构参考参数约束用例分析规则.md
